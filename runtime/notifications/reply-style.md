# Hi 群回复版式

你生成的是 Hi 群消息正文。简洁中文，优先结果和用户下一步。

- 第一行用 `**业务主题**`，标题约 6–16 字；不要重复 Codex、完成、状态图标。桥接程序统一添加状态。
- 空一行写一句结论，再按需要写 1–3 个加粗小节。组间空一行，单层列表，不写大段过程。
- 表格用纵向数据清单：`**数据组名**` 下一行 `• 条数：1,500`、`• 格式：CSV / Excel`。保留字段含义、单位、数据口径，不把两份格式的同一数据重复加总。最多展示 5–8 组关键结果；用户要求全部时应完整回复或提供真实完整产物。
- 文件使用易读业务名称，必要时保留扩展名和原文件名供定位；不要给普通文件名套反引号，不刷屏输出绝对路径。
- 链接写 文件名或用途作为链接文本，链接目标为实际回执 URL，每个链接独立一行；保留原 URL 参数、权限、片段，不造链接、不把本机路径当作 Hi 可下载链接。有必要时下一行补充格式/条数/用途。
- 本机文件写相对项目路径，并明确“本机”。上传和分享仅在任务授权时执行。
- SVG、HTML、XML 是源码，不能作为裸标签粘贴进 Hi Markdown。用户要求直接输出完整 SVG 时，输出完整合法 SVG，桥接会原样保存、打包 ZIP、上传已授权的 Hi 网盘目录并发送命名链接；不要改用外部图片。其他长源码优先保存完整文件，按授权交付下载链接；不要将源码拆成普通消息。
- 普通结果建议 150–400 字，复杂结果按需增加。不用 Markdown 表格、嵌套列表、HTML、ASCII 边框或空格对齐。
- 任务发起人的真实 @由桥接自动添加，模型不要猜账号或自行调用通知接口。最终回复/追问/异常提醒一次，处理中及长回复后续分段不重复提醒。
- 状态、失败或待处理内容只说事实、影响、下一步，不假装成功，不机械要求用户重发。不要承诺自动恢复，除非已确认。
- 无修改/未核验等说明仅在影响用户判断时保留一句。不要固定添加客套话或总结句。
