# 权限与成员空间

| 对象 | 身份来源 | 文件范围 | 外部能力 | 生命周期 |
| --- | --- | --- | --- | --- |
| 所有者群任务 | 规范消息真实 owner | 目标项目 workspace-write/on-request | 任务授权范围内工具 | 群×owner 续原 session |
| 普通成员 | 精确账号 + 实时在群 + 已绑定工作区 | 本人目录写；指定规则/Skill 只读 | 显式启用的受限代理 | 群×账号独立 session |
| 日/周报分析 | 调度器的本次记录 | 只读证据 | 发布由可信脚本执行 | 每次新建，准确 UUID 清理 |
| 守墓人 | G-ID + terminal + session + 实际 effort | 所有者明确授权的治理范围 | full access/never，非成员权限 | 每轮新建，未验收持续保留 |
| 开发者 | D-ID + round + terminal + session | 指定任务副本 | 只交候选代码 | 返工复用原开发 session |

## 三层同时成立

1. **准入**：显示名、引用作者、邮箱域名、网页指令均不授权。默认未绑定工作区的非所有者拒绝。新群只能由所有者触发接入。
2. **文件与发现**：`member_access.filesystem()`、skills.config、个人 `.agents/skills` 入口一致；只做 symlink 不等于限制生效。App Server 回读 activePermissionProfile，实际读写探针验证。
3. **能力代理**：网盘凭据留可信桥接，限制方法、固定云目录、本人 entryId 与稳定操作码。浏览器按账号 profile/socket 和允许域名，浏览器进程也有外层文件沙箱。可用 Skill 的内部链接不扩展读取范围。

真实隔离验收至少覆盖：本人文件可写、共享规则不可写、另一成员和主目录不可读、软/硬链接不可跨界、未授权方法/云文件被拒、错误 profile 不启动 turn、权限撤销后恢复 thread 也生效。测试必须由本机维护者在夹具账号/目录执行，不能读取成员私有业务来证明隔离。

## 实现边界

这是同一 OS 用户下的协作系统，不是多租户容器平台。治理和所有者是可信管理角色；他们的广域主机权限不能当成恶意成员隔离机制。管理员可改配置，不能靠提示词抵御主机管理员。普通成员文件限制依赖实际 Codex 版本与 macOS sandbox；换执行器必须重新实现并验收，不能仅复制 developerInstructions。

网盘代理以部署所有者的云账号操作，群内结果对群成员可见。浏览器域名限制只控制导航范围，不能在同站点内证明所有按钮的业务权限；删除批次等敏感动作需要平台自身 RBAC/代理接口，当前参考实现主要靠任务授权约束这些动作。网络开启也不等于网络层租户隔离。需要强租户保障时使用独立 OS 账号/容器/远端代理，并重新完成验收矩阵。

公共发行默认日报仅取所有者任务/项目会话及整理回执，排除成员目录。若要团队日报，应由成员显式交付脱敏工作回执给聚合器，而不是开放所有人的原始会话。
