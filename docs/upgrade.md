# 迁移与升级

此公共版本用于新部署，不能直接覆盖原作者或其他人的现有 `.codex`。安装器遇到非空目录会停止；同配置重复 init 仅返回 existing，既不修复源文件也不升级运行状态。

## 现有项目接入

1. 在新的 staging 工作区完成 init 与 verify。比对现有 AGENTS、SOP、Skill、任务计划与权限，明确需要合并的模块。
2. 列出精确目标文件和 SHA256，检查 bridge inbox queued/running、outbox pending、治理未验收 jobs 和任务锁。工作中等待，不强停。
3. 备份本次代码和配置；保留原数据库、游标、日期水位、操作码、文档 ID、成员目录和会话归属。规则按主题合并，索引只加短入口，不覆盖人工内容。
4. 在副本验证配置、路径、源码测试和实际权限；正式应用前再次核对基线未变，只更新本次目标。
5. 空闲重载对应服务，检查新进程心跳、实际任务和原 session 续用。失败恢复本次代码/配置，不恢复旧 SQLite 造成数据丢失或重放。

## 公共版相对原实例的变化

- 去掉真实账号、业务 ID、工作路径、服务标签与本机凭据来源，改成显式配置和工作区推导。
- 普通成员默认必须绑定目录；旧版域名广泛准入仅在继承测试夹具中模拟。生产配置保持 `require_member_workspace=true`。
- 不携带个人业务 Skill、个人写作风格、历史报表和成员资料。按本次业务安装具有分发权的 Skill；周报可用项目 writing-style.md 约束语气。
- 浏览器/网盘存储一律按账号哈希，公开新部署没有历史成员特例。既有实例的登录态/回执不能靠重命名猜测迁移，需要逐账号验证。
- 日报默认仅所有者来源，排除成员目录。需要团队汇总时设计显式脱敏回执入口。

升级执行器或更换平台必须重新验收权限、会话字段和外部协议。`source-manifest.json` 是初次抽取原始源码的内容哈希，不是生产部署签名，也不表示之后已泛化文件仍与原始字节相同。
