# 架构与不变量

系统把“谁提出任务”“在哪里执行”“谁能使用哪项能力”“结果如何确认”“失败如何改善机制”分开保存。Agent 负责理解和规划，可信脚本负责身份、范围、状态、外部写入与回执。提示词无法替代实际文件/工具隔离。

## 任务入口

WS 原始事件先持久化再 ACK；长整数序号保持字符串，不经 JavaScript Number 丢精度。轮询补漏与 WS 共用 messageId 去重。规范消息回读检查来源群、真实发送人、可见 @、序号基线、编辑/撤回；执行前再次确认身份及仍在群。附件/直接引用/文档只作资料，不改变权限。

每个群有独立游标，聊天 thread 按群×请求人绑定。浏览器与文件代理按账号绑定，跨群沿用本人状态。业务队列串行；线程异常使服务恢复。重启遇到 running 标 interrupted，不自动重做可能已产生副作用的业务。

结果与 outbox 同事务保存；发送使用持久 operateCode，回读群、机器人和正文。发送超时不能保证 exactly-once；不换通道或操作码猜测重发。外部系统的幂等能力仍是外部前提。

## 自动化

所有模型生成的整理计划和报告先经确定性校验，再由执行器写入。文件整理核对路径、指纹、字节重复、引用修改和依赖；部分完成的 pending_batch 阻止盲重放。日报以成功截止时间覆盖补记，空日报只写完成回执；周报等待当周所有工作日和正式周五截止回执。

日/周报使用一次性 high 独立会话；清理准确归属，清理失败独立补偿。治理使用新 xhigh 会话管理一轮，开发交付唤醒原守墓人；未验收任务使它持续待命。两种生命周期不能混用。

## 知识与反馈

AGENTS 只保留高频边界与索引，SOP 提供顺序、验收和恢复，Skill 决定何时加载哪些规则。错题记录进入候选；根因未知不阻止记录，未经范围复核不能据此自动开发。P0/P1 首次即可启动调查，频率只是优先级依据之一。修复成果回写 SOP/Skill，并通过真实验收形成闭环。
