# 定时任务 SOP

## 1. 适用范围

项目所有者启用文件整理、日报、周报及可选治理巡检。普通成员无调度维护权限。

## 2. 执行前

检查部署配置与任务范围，确认模型、账号、写入目录及通知目标。服务标签由工作区路径生成，不能套用别人的标签。全量任务使用 macOS、有效登录及网络；独立会话依赖 Herdr。息屏不等于系统睡眠、合盖或关机。

## 3. 操作步骤

1. 在 `workspace.json` 启用对应任务。周报必须同时有日报、档案根 ID 和当周全部工作日来源回执；不足时等待，不凑数据。
2. 先在测试目录运行仓库 `scripts/verify.py`，再执行 `scripts/aw.py doctor --root <工作区> --live` 和实际模型只读探针。所有命令从仓库执行，`--root` 指向部署目录。
3. 用 `aw.py service --root <工作区> --task <任务名> generate` 检查 plist；确认后 install。工作任务每 15 分钟唤醒，由脚本按配置时区判断：周一至五 20:00 后整理/日报，周五 21:00 后及周末补跑周报。治理每 60 秒检查、5 分钟启动冷却。
4. 日报/周报每次新建 high 独立 session，只读分析；发布器校验来源、幂等写入并回读后清理准确 UUID、终端和标签页。失败也清理，清理失败仅补清理。治理 session 则保留历史归档，未验收不能清理。
5. 维护 `state.json`、操作码、截止时间和失败次数。日报每天最多 3 次正式尝试，周报每周最多 3 次写作尝试；等待依赖不消耗写作次数。通知失败与业务失败分开，不为补通知重新发布。
6. 停用使用 `service ... stop`，停止前检查任务锁和归属；保留数据和状态。重新启用核对原状态，不能重设基线或重放历史任务。

## 4. 验收

实际截止时间、输入证据、输出对象、回读及清理回执一致。重复触发不重复业务写入；失败恢复不覆盖人工修改。安装服务只算已安装，需真实任务回执才能报告通过。

## 5. 异常处理

缺登录/网络/Herdr → 保留状态，恢复后按窗口补跑；前置日报未完成 → 周报等待；人工修改或父目录变化 → 停止覆盖；任务运行中 → 不强制重启；关机错过执行 → 按下次合规时间窗口补记，不宣称准点保证。
