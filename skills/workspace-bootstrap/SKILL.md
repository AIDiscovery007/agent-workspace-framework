本 Skill 与完整仓库一起使用。`REPO` 为含 BOOTSTRAP.md、scripts/aw.py 的仓库根；`WORK_ROOT` 是用户选定的目标工作区。先识别是否已有部署。

## 新部署

1. **环境与范围。** 检查 Python ≥3.11、目标目录和用户要求模块。完整参考栈见 [部署](../../docs/deployment.md)。现有配置可查询时先查询，凭据仅本机隐藏输入。
2. **core。** 运行 `python3 scripts/aw.py init --root <绝对目标> --profile core`、doctor 和 `python3 scripts/verify.py --node`。core 只生成框架，不启动服务；新目标不得包含已有业务文件。保存输出，必须实际通过后才报告可运行。
3. **full。** 用户需要群聊/常驻/治理时，补齐 [配置契约](../../docs/deployment.md)；准备新的正式目录或按升级流程合并。先验证 CLI 身份、机器人在群、真实 WS 事件、应用回读、真实只读模型回合，再冻结基线与启动服务。测试发送属于部署范围时说明目标和标记后执行；不通知无关群。
4. **能力。** 对每个成员同步真实账号、个人目录、共享只读路径、Skill 发现入口、工具能力与会话指引。配置不等于真实沙箱，按 [权限验收](../../docs/permissions.md)实测允许/拒绝项。
5. **验收。** 执行 [矩阵](../../docs/acceptance.md)。只把本次实际完成的条目标 passed；缺外部授权/登录/依赖用 blocked 或 pending，继续完成独立可做的模块。服务启动不代替业务闭环。

## 已有部署

读取 [升级](../../docs/upgrade.md)。先确认队列/任务空闲，备份精确文件和指纹；保留状态库、操作码、用户人工修改及 session 归属。差异逐项合并，失败回滚本次代码/配置，不能恢复旧库重放任务。

## 必须保持

- 普通成员按可信账号绑定目录，缺绑定拒绝。共享规则可读不授予全局写权限；外部工具凭据留可信代理。
- 独立 session 与子 Agent 分开。Herdr 使用 `codex --no-daemon` 和真实 space/terminal ID，核验可见终端与实际 session；不以内部 thread 代替。
- full-access 治理仅在所有者明确启用后启动：守墓人 xhigh、开发 high、纯执行 medium。不得把治理权限套给群成员。
- 共享失败按 record-incident 提交事实。次数不是治理门槛；原守墓人亲自测试验收全部任务后才归档。
- 不分发登录态、历史成员资料或运行日志。测试只在夹具目录，不把模拟事件写进真实错题库。

交付至少包含工作区位置、真实执行范围、测试与外部验收差异、待用户完成的具体依赖、已启动服务及停止命令。读取本 Skill 不是完成部署。
